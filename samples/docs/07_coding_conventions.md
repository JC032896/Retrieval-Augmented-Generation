# 개발 코딩 컨벤션

## 언어별 규칙

### Python

- 포매터와 린터는 ruff를 쓴다. 한 줄 길이는 100자로 한다.
- 함수와 변수 이름은 snake_case, 클래스 이름은 PascalCase로 쓴다.
- 공개 함수에는 타입 힌트를 반드시 붙인다.

### TypeScript

- 포매터는 Prettier, 린터는 ESLint를 쓴다.
- `any` 타입은 쓰지 않는다. 불가피하면 PR 설명에 이유를 적는다.

## 브랜치와 커밋

- 브랜치 이름: `feature/HB-<이슈 번호>-<짧은 설명>`, 버그 수정은 `fix/HB-<이슈 번호>`
- 커밋 메시지 첫 줄: `[HB-<이슈 번호>] 변경 요약` 형식으로 50자 이내로 쓴다.
- main 브랜치에 직접 push하지 않는다.

## 코드 리뷰

- 모든 PR은 리뷰어 2명의 승인을 받아야 병합할 수 있다.
- 리뷰 요청을 받으면 1영업일 이내에 첫 리뷰를 남긴다.
- PR 하나의 변경량은 400줄 이내를 권장한다.

## 테스트

- 새 코드의 테스트 커버리지는 80% 이상이어야 한다.
- CI가 실패한 PR은 병합할 수 없다.

## 배포

- 정기 배포는 매주 화요일과 목요일 오후 2시에 한다.
- 금요일과 공휴일 전날에는 배포하지 않는다. 긴급 장애 수정은 예외이며, 이때는 장애 대응 매뉴얼을 따른다.
